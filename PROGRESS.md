## Next up

**M3 — Raster and halftone pipeline** (SPEC.md 6.2, 6.3, 7.1; milestone M3 in section 9).

1. `include/m2022/raster.h`, `src/raster/`: ingest 8-bit sGray (and 1-bit black, sRGB→gray for
   safety) lines into a page buffer; tone curve as a 256-entry LUT built from gamma and dot-gain
   parameters; crop/pad to the printable area for a media size (12.5 pt margins); upscale 300→600
   if a client ever sends 300. Pure, no I/O.
2. `include/m2022/halftone.h`, `src/halftone/`: threshold; Bayer ordered dither (4×4, 8×8);
   clustered-dot ordered screen (like the vendor's ~45° screen seen in `decode` output);
   Floyd–Steinberg with serpentine scan; Ostromoukhov variable-coefficient error diffusion;
   blue-noise mask (void-and-cluster generated by `scripts/gen-bluenoise.py`, checked in as a C
   table). Output 1 = black, packed rows. Presets Draft/Normal/Text/Photo per SPEC 7.1.
3. `m2022-airbridge render IN.pgm --preset normal --out page.pbm` (also accepts the captured
   `artifacts/capture/job-*.pgm` and the vendor CUPS rasters from `fixtures/oracle/samsung/*.ras.gz`,
   which are 8-bit K where 255 = black).
4. Tests: every algorithm on 8×8 hand-checked references; determinism; ramp monotonicity;
   and a comparison test: halftone the vendor's own input raster (`small-text-a4.ras.gz`) and
   compare with the vendor's output bitmap (`decode --pbm` of `small-text-a4.spl`): text pixels
   should agree closely under the Text preset; report agreement, do not require identity.
5. Docs: `docs/raster.md`, `docs/halftone.md` with pictures of each algorithm on the ramp and the
   photo fixture (PNG previews under artifacts/, described in the doc).

Start by reading SPEC.md 6.2, 6.3, 7.1 and section 10 (halftoning reading list), then look at a
decoded vendor page (`m2022-airbridge decode fixtures/oracle/samsung/photo-a4.spl --pbm /tmp/v`)
to see the screen we are matching.

## Facts established (details in `docs/`)

- The printer's language is fully decoded and verified against 42 captured jobs, 867 bands:
  `docs/spl-qpdl.md`. Compression is 0x11 (not JBIG), band width = ceil(raster width / 256) × 256,
  offset tables vary per band, "Best" is a real 1200 dpi mode.
- USB access works unprivileged with libusb; the device ID advertises `URF`: `docs/usb.md`.
- The vendor driver is Intel-only and stops working with macOS 28 (fall 2027). Its package is
  backed up under `artifacts/vendor-driver-backup/` (gitignored: keep a copy elsewhere too).
- Open hardware questions live in SPEC.md section 16 (PJL lines required, copies field, 1200 dpi
  print quality, toner channel, raw URF over USB).

## Environment notes

- Build: `export PATH=/opt/homebrew/bin:$PATH; cmake -S . -B build -G Ninja; cmake --build build;
  ctest --test-dir build --output-on-failure -LE hardware`
- Hardware tests print pages: `ctest --test-dir build -L hardware` only with the printer on.
- Run the application for client tests: `./build/src/m2022-airbridge server --capture artifacts/capture --spool build/run/spool --log build/run/server.log`; stop with `pkill -f 'm2022-airbridge server'`.
- Recapturing vendor fixtures needs the Intel vendor filter under Rosetta; do not delete the
  vendor driver before M7, and never regenerate the oracle files casually.
- `scripts/spl-survey.py` and `m2022-airbridge decode` are the tools for studying jobs.
